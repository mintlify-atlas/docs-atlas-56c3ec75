Horion's friend list is a shared, in-memory roster of player names that combat modules consult before selecting a target. Any player on the list is treated as an ally — modules that use `Target::isValidTarget()` will skip them entirely when scanning for targets. Adding your teammates before entering combat is one of the most important steps you can take to prevent accidental team-kills.

## How It Works

The `FriendList` class (`FriendList/FriendList.h`) maintains a `std::vector<std::string>` of player names behind a set of static accessor methods:

```cpp
class FriendList {
private:
    std::vector<std::string> List;

public:
    static std::vector<std::string> getList();
    static bool findPlayer(const std::string& name);
    static bool findPlayer(const char* name);
    static void addPlayerToList(const std::string& name);
    static bool removePlayer(const std::string& g);
};

extern FriendList g_friend;
```

The global `g_friend` instance is the single source of truth. All four methods operate on it statically, so any module or command can read or modify the list without holding a reference to the object.

### Lookup Behaviour

`findPlayer` uses a **substring search** (`std::string::find`), not an exact match:

```cpp
bool FriendList::findPlayer(const std::string& name) {
    for (auto it = g_friend.List.begin(); it != g_friend.List.end(); ++it) {
        if (it->find(name) != std::string::npos) {
            return true;
        }
    }
    return false;
}
```

This means a friend entry of `"Steve"` will match both `"Steve"` and `"SteveBuilder"`. In practice this is rarely a problem, but use precise names to avoid unintended matches.

`removePlayer` uses a case-insensitive substring search before erasing the entry:

```cpp

```

## Modules That Respect the Friend List

The shared `Target::isValidTarget()` helper in `Utils/Target.cpp` performs the friend-list check and is used by every module that needs to pick a combat target. When `NoFriends` is disabled, any player whose name matches an entry in the list is excluded from targeting. Modules that call `Target::isValidTarget()` include:

## Managing Friends In-Game

The `FriendListCommand` exposes add and remove operations through the standard command prefix. It also registers `friendlist` as an alias.

```
.friend add <name>      — add a player to the friend list
.friend remove <name>   — remove a player from the friend list
```

<Note>
The `add` subcommand resolves the player name from the current entity list — the target player must be visible in the world when the command is run. The name is stored exactly as it appears on their name tag.
</Note>

<Steps>
  <Step title="Add a friend">
    ```
    .friend add Notch
    ```
    Searches the active entity list for a player whose name contains `"notch"` (case-insensitive), then calls `FriendList::addPlayerToList()` with their exact name tag. The player is protected immediately — no reload or restart required.
  </Step>
  <Step title="Remove a friend">
    ```
    .friend remove Notch
    ```
    Calls `FriendList::removePlayer("notch")` (the command lowercases the input). Returns `true` if a matching entry was found and erased.
  </Step>
</Steps>

## Persistence

<Warning>
The friend list is stored **in memory only** and is **not** saved to the config file. Your friend list will be cleared every time Minecraft exits. Re-add teammates at the start of each session, or use the MidClick module (scroll-wheel) for quick in-game management.
</Warning>

## The `NoFriends` Module

`NoFriends` is a toggle module in the `PLAYER` category that temporarily suspends all friend-list checks. When it is enabled, `Target::isValidTarget()` ignores the friend list and all modules that depend on it will target every nearby player regardless of friend status.

<Warning>
`NoFriends` is a global override — enabling it affects **all** combat modules simultaneously. Only enable it when you are certain no teammates are nearby, such as in a solo PvP scenario where you want to test a module's targeting behaviour.
</Warning>

## Best Practices

<Tip>
Add every teammate to your friend list before enabling any combat module in a multiplayer session. A single `.friend add <name>` takes under a second and eliminates the risk of an accidental team-kill.
</Tip>

- Use precise, correctly capitalised names — `addPlayerToList` stores the name exactly as typed from the name tag, so inconsistent capitalisation can create duplicate entries.
- Use the **MidClick** module (`PLAYER` category) to toggle friends on and off quickly with your mouse wheel while looking at a player, without typing a command.
- Because the friend list resets on each launch, consider keeping a text file or config note with your regular teammates' names so you can re-add them quickly.
